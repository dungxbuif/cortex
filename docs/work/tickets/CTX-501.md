# CTX-501: Audit Logging API

## Context

The raw spec requires a shared append-only audit/event model for permission decisions, sync/index lineage, tool calls, writes, denies, and debugging. This ticket implements the audit primitive before orchestrator and capability guard integration.

## Scope

- Add `audit_events` PostgreSQL migration.
- Add Go audit module with append/get/list APIs.
- Validate required event fields and status values.
- Reject secret-looking metadata/source/target keys before persistence.
- Add focused unit/integration tests for append/query/validation behavior.

## Out of Scope

- Public HTTP audit browsing API.
- Full Orchestrator event emission.
- Retrofitting every existing module call to emit audit events.
- Role-level DB grants/triggers for hard append-only enforcement.

## Acceptance Criteria

- [ ] `audit_events` table and indexes are defined in a migration.
- [ ] `AppendEvent` persists immutable event records with generated event IDs and timestamps.
- [ ] `GetEvent`, `ListEvents`, `ListEventsByRequest`, and `ListModuleTimeline` return expected records.
- [ ] Validation rejects missing required fields and unsupported status values.
- [ ] Validation rejects secret-looking keys in metadata/source/target refs.
- [ ] Tests pass and evidence is recorded.

# Ticket: CTX-710 Finance Connector, Read Tools

## Context

The Python orchestrator needs to map natural language intents for Finance queries to the gRPC service bridge. To prevent blockages between Go and Python development, the connector should support local mocking using a fake gRPC client wrapper during test runs.

## Scope

- Implement `FinanceConnector` implementing `ModuleConnector` in Python.
- Register read-only tools:
  - `finance_list_wallets`
  - `finance_list_categories`
  - `finance_get_financial_report`
  - `finance_get_net_worth`
- Connect tools to `FinanceGrpcClient` client wrapper.
- Create a `FakeFinanceGrpcClient` in Python:
  - Mocks Go Finance data return structures offline.
  - Allows local ReAct loop testing independent of Go server availability.
- Ensure any write intents (e.g. creating transactions) return a safe "unsupported/future-scope" observation.

## Out of Scope

- Enabling Finance writes in the registry.

## Acceptance Criteria

- [ ] `FinanceConnector` matches tool registration schemas.
- [ ] Read tools invoke client calls and translate responses to standard `ToolObservation` formatting.
- [ ] `FakeFinanceGrpcClient` mocks reports, net worth, and wallet listings successfully.
- [ ] Non-read intents or writes return fallback observation status.
- [ ] Unit tests verify connector behavior using the mock client.

## Small Task Exemption

- Small task exemption: no

## Test Expectations

- Unit tests verifying tool execution mapping and response parsing using `FakeFinanceGrpcClient` offline.

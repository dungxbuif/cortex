# Ticket: CTX-701 Conversation and Confirmation State

## Context

Telegram bots are stateless. To support multi-turn conversation context and multi-turn confirmation prompts (e.g. confirming high-impact operations like Finance writes), the Python orchestrator needs local database storage.

## Scope

- Create and apply PostgreSQL migrations in the Python AI service for three new tables:
  - `conversations`: Primary keys mapping owner IDs, transport channels (e.g., 'telegram'), and chat IDs.
  - `conversation_messages`: Stores sequential message turns (user query, assistant tool calls, tool results/observations, and assistant synthesized text).
  - `pending_confirmations`: Stores details of actions that require explicit user approval (action parameters, target tool, parameter hash for integrity check, expiration timestamp, and target actor details).
- Implement `ConversationManager` to expose:
  - `load_conversation(owner_id, channel, channel_ref)`: Retrieve conversation history, trimming it according to context-window policy (default: last 20 messages or 8000 tokens).
  - `save_message(conversation_id, role, content, tool_calls, tool_result)`: Persist conversation turns.
  - `create_pending_confirmation(conversation_id, tool_name, tool_args, policy_decision, prompt_shown, ttl_seconds)`: Save a new confirmation record.
  - `get_active_confirmation(conversation_id)`: Retrieve active confirmation, checking expiration (default 5-minute TTL) and actor binding.
  - `resolve_confirmation(confirmation_id, status)`: Update confirmation status to `confirmed`, `declined`, or `expired`.
- Add integration tests verifying schema setup and correct state transitions.

## Out of Scope

- Implementing the Telegram bot network logic.
- Implementing the LLM/ReAct execution flow.
- Calling the Go policy or audit services.

## Acceptance Criteria

- [x] DB migration files for `conversations`, `conversation_messages`, and `pending_confirmations` compile and apply cleanly.
- [x] ConversationManager can save and retrieve messages within the context window limits.
- [x] Context loading enforces conversation reset after 24 hours of inactivity.
- [x] Pending confirmations enforce correct TTL expiration, parameter validation via SHA-256 hash, and user/channel actor binding (one user cannot approve another's action).
- [x] Integration tests verify migration and manager logic against local PostgreSQL.

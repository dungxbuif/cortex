# Ticket: CTX-701 LLM/ReAct Runtime And Prompt Contract

## Context

Epic 4 added a deterministic Python gateway router. This ticket replaces the stub router with a real LLM/ReAct runtime while preserving module boundaries.

This implementation ticket depends on `CTX-701A`, which defines the human-reviewed prompt contract and orchestration decision flow before runtime code is changed.

## Scope

- Implement the approved `CTX-701A` prompt and decision-flow design.
- Define system/developer prompt contracts for Cortex.
- Implement provider invocation for chat reasoning using configured model provider.
- Add ReAct loop state: observe, choose tool, execute, synthesize, clarify, or stop.
- Add deterministic guardrails for max turns, timeout, provider failure, and no-tool fallback.

## Out of Scope

- Tool execution implementation beyond using the tool registry interface.
- Permission/audit persistence.
- Domain business logic changes.

## Acceptance Criteria

- [ ] Runtime can answer no-tool prompts.
- [ ] Runtime can request a tool call when tool schemas are supplied.
- [ ] Runtime asks a clarification question when required arguments are missing.
- [ ] Prompt contracts keep domain modules free of prompts and LLM schemas.
- [ ] Unit tests cover stop, clarify, tool-call, provider-error, and max-turn paths.

## Small Task Exemption

- Small task exemption: no

## Test Expectations

- Unit tests with fake provider responses.
- Integration smoke with configured Google model gated by opt-in env.

# Ticket: CTX-711 Presentation, Health, and Graceful Degradation

## Context

The user experience in Telegram must be premium and readable. The orchestrator must format Markdown tables, aggregate RAG citations cleanly, and gracefully handle component failures (like a disconnected Go gRPC bridge or missing search indexes) instead of throwing errors.

## Scope

- Implement presentation rules:
  - Aggregate multiple source citations at the end of RAG responses using descriptive labels (note paths, commit SHAs).
  - Format list and summary data structures (like Finance net worth and reports) as clean Markdown tables.
  - Apply MarkdownV2 character escaping safely to avoid Telegram API exceptions.
- Implement system and module health checks:
  - Monitor module and provider health status.
  - Detect stale search indexes (e.g. if vault syncing metadata is older than 24 hours) and append a gentle warning in response.
- Implement graceful degradation:
  - If a gRPC service (Finance, Policy, Audit) is offline, route to a controlled fallback message ("Dịch vụ tạm thời không khả dụng") instead of crashing the orchestrator loop.

## Out of Scope

- Setting up polling/webhook Telegram adapters (handled in CTX-702).

## Acceptance Criteria

- [ ] Citation lists render cleanly with correct formatting constraints.
- [ ] Financial data is parsed into aligned Markdown tables.
- [ ] MarkdownV2 escaping handles special characters without triggering Telegram API rendering errors.
- [ ] Stale search index warnings are successfully appended to RAG answers when sync checks fail.
- [ ] Mismatched or offline Go components result in clean fallback notifications.
- [ ] Unit tests cover formatter and fallback middleware logic.

## Small Task Exemption

- Small task exemption: no

## Test Expectations

- Unit tests for formatting templates, Markdown V2 escaping edge cases, stale index checks, and gRPC failure fallbacks.

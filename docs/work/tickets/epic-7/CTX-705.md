# Ticket: CTX-705 Policy/Audit gRPC Bridge

## Context

Epic 5 implemented Go system services for persistent `audit_events` and static v1 capability/policy decisions. To check permissions, verify confirmation rules, and log tool actions from the Python runtime, the orchestrator needs a gRPC bridge to the Go backend services.

## Scope

- Define gRPC service definitions in `src/proto/cortex.proto`:
  - `PolicyService`: Evaluates requests against static capability tables and confirmation rules.
  - `AuditService`: Appends immutable audit records for tool executions, denials, or system state updates.
- Compile protobuf stubs for both Go and Python runtimes.
- Wire Go backend services to expose gRPC servers:
  - Connect gRPC handlers in Go to the existing `internal/modules/system/policy` and `internal/modules/system/audit` implementations.
- Implement Python client wrappers (`PolicyGrpcClient`, `AuditGrpcClient`) to interact with these Go servers.
- Implement synchronous Python interfaces in the orchestration middleware to easily check policies and emit audits.

## Out of Scope

- Implementing new policy tables or changing audit database tables.
- UI changes.

## Acceptance Criteria

- [ ] gRPC stubs compile successfully for Go and Python.
- [ ] Go gRPC servers launch and bind to backend services.
- [ ] Python clients connect to Go services and correctly map responses.
- [ ] Policy decisions (Allow, Deny, Require Confirmation) are evaluated correctly across the gRPC bridge.
- [ ] Tool executions successfully emit persistent audit events in PostgreSQL.
- [ ] Integration tests verify end-to-end gRPC communication between Go server and Python client.

## Small Task Exemption

- Small task exemption: no

## Test Expectations

- Integration tests checking Python-to-Go gRPC connectivity, capability policy checks, and audit logging database verification.

# Ticket: CTX-704 Tool Registry And Provider Conversion

## Context

The orchestrator needs a clean, provider-neutral registry of allowed tools that can be dynamically parsed, filtered, validated, and translated into provider-specific schemas (like Gemini or OpenAI formats) at runtime.

## Scope

- Implement a YAML/JSON-driven `ToolRegistry` that loads tool specifications including:
  - Name, description, parameter schemas (JSON Schema), target API, required capability, confirmation policy, output contract, and audit event name.
- Enforce schema validation:
  - Validate candidate arguments proposed by the LLM using `jsonschema`.
  - Extract and normalize data types before executing tools.
  - Return validation error feedback observations back to the LLM during the ReAct loop (with a max retry limit before clarifying).
- Implement conversion adapters:
  - Translate provider-neutral tool schemas into Google Gemini (and optionally OpenAI) tool call declaration structures.
  - Support filtering tools by capability, module health, or owner contexts.

## Out of Scope

- Execution of domain connectors.
- Multi-turn database conversation logging.

## Acceptance Criteria

- [ ] `ToolRegistry` parses and registers tools correctly with all metadata fields.
- [ ] Schema validation rejects invalid parameter inputs and outputs clear error observations.
- [ ] Mismatched or unauthorized tools are excluded from the LLM prompt.
- [ ] Provider adapters translate schemas to Google Gemini FunctionDeclarations accurately.
- [ ] Tests verify schema validation, type mapping, and provider schema translation.

## Small Task Exemption

- Small task exemption: no

## Test Expectations

- Unit tests for schema enforcement, type parsing, and Google/OpenAI converter correctness.

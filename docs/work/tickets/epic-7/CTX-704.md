# Ticket: CTX-704 Telegram Bot Transport Adapter

## Context

Epic 7 uses Telegram as the single user-facing chat surface. The orchestrator core already accepts transport-neutral `ConversationInput`, so CTX-704 adds a Telegram adapter that normalizes Telegram updates, enforces a Telegram user/chat allowlist, formats outbound HTML safely, chunks long responses, and leaves actual reasoning to an injected orchestration handler.

## Scope

- Normalize Telegram text updates into `ConversationInput`.
- Enforce explicit Telegram user/chat allowlist mapped to the Cortex owner.
- Send Telegram typing actions before long orchestration calls.
- Escape outbound text for Telegram `HTML` parse mode.
- Convert common Markdown-lite output (`**bold**`, `*italic*`, links, inline code, fenced code) into Telegram-safe HTML.
- Use plaintext chunking for long outbound messages over Telegram's 4096 character limit to avoid split HTML tags.
- Retry outbound messages as plain text when Telegram rejects HTML.
- Load bot token, allowlist, and chunk target from environment for runtime composition.
- Provide optional `python-telegram-bot` application wiring at the network boundary.
- Keep core adapter behavior unit-testable without Telegram network calls.

## Out of Scope

- Real LLM/provider behavior.
- Tool execution and module connector implementation.
- Production webhook deployment.
- Multi-user identity beyond the explicit Telegram allowlist.

## Acceptance Criteria

- [x] Adapter normalizes Telegram text messages into `ConversationInput` with owner, actor, channel, chat, user, content, request ID, and Telegram metadata.
- [x] Unauthorized Telegram chat/user pairs are rejected before orchestration handler execution.
- [x] Adapter sends a typing action before invoking the orchestration handler.
- [x] Outbound model text is HTML-escaped before sending with Telegram `HTML` parse mode.
- [x] Common Markdown-lite output is rendered as Telegram-safe HTML for better chat UX.
- [x] Long outbound responses are sent as plaintext chunks under Telegram's 4096 character limit.
- [x] Chunking avoids splitting inside HTML entities.
- [x] HTML send failures retry with a plain-text fallback.
- [x] Runtime settings can be loaded from Telegram environment variables.
- [x] Optional `python-telegram-bot` wiring exists without making unit tests depend on network calls.
- [x] Tests cover normalization, allowlist denial, HTML escaping, Markdown-lite rendering, long plaintext chunking, fallback, env settings, and ignored non-text updates.

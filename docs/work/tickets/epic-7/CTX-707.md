# Ticket: CTX-707 Finance gRPC Bridge & Connector (Read Scope)

## Context

The Go Finance module holds all business logic and canonical database models, but lacks a gRPC API that the Python orchestrator can call. The orchestrator must not query Finance database tables directly. We need to implement a read-only gRPC service bridge.

## Scope

- Define the `FinanceService` interface in `src/proto/cortex.proto` supporting:
  - `HealthCheck`: Service health.
  - `ListWallets`: Returns summary list of accounts.
  - `ListCategories`: Returns configuration list of categories.
  - `GetFinancialReport`: Returns income/expense summaries over period.
  - `GetNetWorth`: Returns net asset/liability report.
- Compile protobuf stubs for both Go and Python runtimes.
- Implement the Go Finance gRPC server:
  - Connect gRPC handlers to the existing Go Finance queries (`internal/modules/finance/service`).
  - Represent all money amounts as `int64 minor_units` with a separate `currency` string (e.g. VND).
- Implement Python `FinanceGrpcClient` client wrapper.
- Implement Python `FinanceConnector` for mapping tool calls.
- Register Finance read tools in the Tool Registry.
- Create integration tests verifying client-server communication.

## Out of Scope

- Exposing write methods (`CreateTransaction`, `CreateTransfer`, etc.) - these will remain disabled.
- Direct database calls from Python to Finance tables.

## Acceptance Criteria

- [x] `FinanceService` proto definitions compile for Go and Python.
- [x] Go gRPC server compiles and connects to Go Finance queries.
- [x] Money representations use minor units and explicit currency fields.
- [x] Python `FinanceGrpcClient` client connects, authenticates, and retrieves reports/wallets.
- [x] Integration tests verify server-client exchange of financial data.

## Small Task Exemption

- Small task exemption: no

## Test Expectations

- Integration tests checking Python client connection to Go gRPC backend server, requesting wallets, categories, net worth, and reports.

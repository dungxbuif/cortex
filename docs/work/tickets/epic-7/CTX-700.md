# Ticket: CTX-700 Shared Orchestration Contracts

## Context

The Python orchestrator needs a stable set of core data models, connector interfaces, and a registry to decouple the orchestration state flow from specific transport channels (like Telegram) and specific domain module integrations (Finance, Second Brain, Homelab).

## Scope

- Define Python data models and types for key orchestration contracts:
  - `ConversationInput`: Represents the incoming chat query, chat identifier, user/actor details, and source channel info.
  - `ToolExecutionContext`: Bundles execution metadata such as owner ID, actor ID, actor type, conversation ID, request ID, channel, and confirmation ID.
  - `ToolObservation`: Standardizes the structure of tool execution results containing status, module name, tool name, safe user message, raw dictionary data, citations, warnings, and optional audit event ID.
- Define the `ModuleConnector` protocol/interface in Python with asynchronous methods:
  - `health(self) -> ModuleHealth`
  - `supported_targets(self) -> set[str]`
  - `execute(self, tool_name: str, target_api: str, args: dict, context: ToolExecutionContext) -> ToolObservation`
- Define `ConnectorRegistry` to register, retrieve, and validate connectors:
  - Implement `validate_tools(self, tool_registry: ToolRegistry)` to run startup checks comparing tool registry schemas against the connector `supported_targets()`. Fail fast if there is a mismatch.

## Out of Scope

- Implementing real connectors for Second Brain, Homelab, or Finance.
- Database storage implementation for conversation histories or confirmations.
- Loading prompts or calling LLM APIs.

## Acceptance Criteria

- [ ] `ConversationInput`, `ToolExecutionContext`, and `ToolObservation` are implemented as Python dataclasses or Pydantic models.
- [ ] `ModuleConnector` protocol defines standard execution and health contracts.
- [ ] `ConnectorRegistry` successfully registers and retrieves connectors by module identifier.
- [ ] Registry validation fails fast at startup if a registered tool maps to an unsupported target API.
- [ ] Unit tests cover registration, retrieval, and validation mismatch checks.

## Small Task Exemption

- Small task exemption: no

## Test Expectations

- Unit tests for registry operations and validation checks with mock connectors.

# CTX-502: Capability Guard Middleware

## Context

The raw spec requires policy enforcement before tool/API calls. This ticket implements the capability guard as a pure Go service first, with audit emission for write/sync/index/RAG decisions. HTTP middleware and Orchestrator wiring can wrap this service later.

Current Second Brain webhook sync authenticates with a shared static token from environment configuration. That token proves the caller knows a secret, but it does not yet prove the caller is authorized for a specific capability such as `second_brain.index_external_source`, and it does not create a durable audit trail for security monitoring.

## Scope

- Add Go policy module with static v1 module/capability matrix.
- Evaluate allow, deny, require-confirmation, require-clarification, and require-manual-action decisions.
- Enforce hard read-only boundaries for Homelab and Second Brain external writes.
- Emit audit events for write/sync/index/RAG policy decisions through an audit sink.
- Support webhook/system actors such as n8n by evaluating `second_brain.index_external_source` before Second Brain external indexing jobs are accepted or executed.
- Add focused tests for allow/deny/confirmation/audit behavior.

## Out of Scope

- Full Orchestrator tool registry.
- Public policy management UI/API.
- Dynamic policy persistence.
- Auth/session role model.

## Acceptance Criteria

- [x] Known allowed capabilities return `allow`.
- [x] Unknown modules/capabilities return `deny`.
- [x] Homelab repo write/runtime action requests return `deny`.
- [x] Second Brain direct Vault write requests return `deny`.
- [x] High-impact Finance write requests return `require_confirmation`.
- [x] Confirmation cannot override hard denial.
- [x] Write/sync/index/RAG decisions append audit events.
- [x] Webhook/system actor evaluation can allow or deny `second_brain.index_external_source`.
- [x] Tests pass and evidence is recorded.

# CTX-502: Capability Guard Middleware

## Context

The raw spec requires policy enforcement before tool/API calls. This ticket implements the capability guard as a pure Go service first, with audit emission for write/sync/index/RAG decisions. HTTP middleware and Orchestrator wiring can wrap this service later.

## Scope

- Add Go policy module with static v1 module/capability matrix.
- Evaluate allow, deny, require-confirmation, require-clarification, and require-manual-action decisions.
- Enforce hard read-only boundaries for Homelab and Second Brain external writes.
- Emit audit events for write/sync/index/RAG policy decisions through an audit sink.
- Add focused tests for allow/deny/confirmation/audit behavior.

## Out of Scope

- Full Orchestrator tool registry.
- Public policy management UI/API.
- Dynamic policy persistence.
- Auth/session role model.

## Acceptance Criteria

- [ ] Known allowed capabilities return `allow`.
- [ ] Unknown modules/capabilities return `deny`.
- [ ] Homelab repo write/runtime action requests return `deny`.
- [ ] Second Brain direct Vault write requests return `deny`.
- [ ] High-impact Finance write requests return `require_confirmation`.
- [ ] Confirmation cannot override hard denial.
- [ ] Write/sync/index/RAG decisions append audit events.
- [ ] Tests pass and evidence is recorded.

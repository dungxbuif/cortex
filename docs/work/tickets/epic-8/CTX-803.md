# CTX-803: Unified RustFS Webhook Ingestion (Second Brain & Homelab)

## Problem
Currently, Second Brain relies on MinIO/S3 Webhooks, and Homelab was designed to rely on GitHub Events. The user is now standardizing on a local **RustFS** file watcher to monitor file changes across both the Second Brain vault and the Homelab repository. We need a unified API route to ingest file events from RustFS and trigger the appropriate async indexing/delete jobs, and we need to mock test this new flow.

## Outcome
- A generic `POST /v1/webhooks/rustfs` endpoint in the Python FastAPI layer (`src/ai_service/api.py`) that accepts events for any domain (`second_brain` or `homelab`).
- RustFS payload parsing that delegates to the existing Ingestion Jobs system (which currently handles MinIO events).
- Integration tests simulating RustFS payload deliveries to trigger index updates and deletions without requiring a running RustFS process.

## Proposed Setup & Architecture (Research)

### 1. The RustFS Webhook Payload
Since RustFS is a local file watcher, it should be configured to emit a standardized JSON payload via HTTP POST when a file change occurs:

```json
{
  "source": "rustfs",
  "domain": "second_brain", // or "homelab"
  "event_type": "write",    // "write", "create", "remove", "rename"
  "absolute_path": "/Users/dungxbuif/workspace/second-brain/wiki/project.md",
  "relative_path": "wiki/project.md",
  "timestamp": 1718928123
}
```

### 2. The API Route (FastAPI)
In `src/ai_service/api.py`, add a unified route to receive events:
```python
@app.post("/v1/webhooks/rustfs")
async def rustfs_webhook(payload: dict, background_tasks: BackgroundTasks):
    # 1. Verify standard payload fields
    # 2. Map `event_type` to Upsert or Delete job
    # 3. Create an IngestionJob in the database
    # 4. Return 202 Accepted immediately
```

### 3. File Retrieval (Local Pathing)
Currently, `submit_minio_event` uses `sync_minio_object` which fetches from MinIO. With RustFS, the file is already on the local disk. Cortex can bypass MinIO entirely and read the file directly using standard Python file IO (`open(absolute_path, "r")`), then pass the string to the existing semantic chunker.

### 4. Mock Testing Strategy
- Create `src/ai_service/tests/test_rustfs_webhook.py`.
- Spin up `fastapi.testclient.TestClient`.
- **Test 1 (Upsert)**: Create a temporary markdown file locally. Send a mocked `POST /v1/webhooks/rustfs` JSON payload. Verify that `process_ingestion_job` reads the local file and upserts chunks into pgvector successfully.
- **Test 2 (Delete)**: Delete the local file. Send a mocked `remove` event payload. Verify the worker clears the pgvector chunks for that document.

## Out of Scope
- Actually writing the RustFS daemon in Rust (handled externally by the user).

## Acceptance
- [ ] `POST /v1/webhooks/rustfs` correctly parses standard RustFS JSON payloads.
- [ ] `write`/`create` events successfully index local files directly from disk.
- [ ] `remove` events successfully clear stale chunks from the database.
- [ ] Mock tests pass for both Second Brain and Homelab payloads.

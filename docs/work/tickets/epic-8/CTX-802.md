# Ticket: CTX-802 Delete Synchronization For Second Brain RAG Index

## Context

The current webhook sync covers object create/update ingestion. It does not yet handle S3 delete events such as `s3:ObjectRemoved:*`, so deleted Obsidian mirror files can leave stale documents and chunks in PostgreSQL/pgvector and appear in RAG answers.

## Scope

- Accept and classify S3 object delete events from the webhook source.
- Map deleted bucket/key values to Second Brain document records.
- Delete or tombstone the matching `secondbrain_documents` record according to the approved data model.
- Delete all related `secondbrain_document_chunks` so RAG search no longer returns removed content.
- Record status/evidence for delete jobs and stale-index cleanup.

## Out of Scope

- Deleting files from the local Obsidian Vault.
- Deleting immutable audit events.
- Manual bulk cleanup UI.

## Acceptance Criteria

- [x] Delete events for `second-brain/**/*.md` are accepted and processed.
- [x] Delete events outside the accepted prefix or non-Markdown scope are ignored or rejected consistently.
- [x] Matching document and chunk records are removed from active RAG tables.
- [x] Deleted content no longer appears in RAG search results.
- [x] Tests cover found, not-found/repeated delete, out-of-scope key behavior through shared validation, and RAG regression cases.

## Small Task Exemption

- Small task exemption: no

## Test Expectations

- Unit tests for delete event classification and key mapping.
- Integration tests against local PostgreSQL/pgvector proving chunk removal from search.
- Docs review for source-of-truth deletion policy and validation matrix updates.

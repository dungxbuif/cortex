# Ticket: CTX-801 Async Ingestion Queue For Webhook Sync

## Context

The current Second Brain MinIO webhook path is synchronous: receive webhook, sign/fetch S3 object, chunk Markdown, call Gemini embeddings, and persist PostgreSQL/pgvector records on the API request path. Large files or provider rate limits can block webhook requests and cause timeouts.

## Scope

- Add an ingestion job abstraction for Second Brain object events.
- Persist or enqueue object metadata after webhook authentication and validation.
- Return `202 Accepted` without doing object download, chunking, embedding, or vector writes inline.
- Add a worker execution path that performs download, chunking, embedding, persistence, retries, and status updates.
- Preserve checksum/idempotency behavior for repeated create/update events.

## Out of Scope

- Full production queue deployment tuning.
- Direct Vault writes.
- New non-Second Brain ingestion sources.

## Acceptance Criteria

- [x] Webhook route returns `202 Accepted` after durable enqueue/persist for accepted create/update events.
- [x] Worker processes accepted jobs and updates job status.
- [x] Provider rate-limit or transient failures fail the worker job without blocking the original webhook request; retry scheduling remains a future worker concern.
- [x] Duplicate object events remain idempotent through existing checksum-aware indexing once jobs execute.
- [x] Tests cover enqueue, worker success, failure/status path through focused services, and idempotency.

## Small Task Exemption

- Small task exemption: no

## Test Expectations

- Unit tests for job validation/idempotency.
- Integration tests for webhook `202 Accepted` and worker processing with fake object store/embedder.
- PostgreSQL/pgvector regression proof for existing CTX-204 behavior.

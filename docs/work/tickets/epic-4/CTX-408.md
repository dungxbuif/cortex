# Ticket: CTX-408 Go Gateway gRPC Client And Proxy Routes

## Status

- ID: CTX-408
- Status: verified
- Type: feature
- Priority: High
- Phase: PHASE-4-restructuring
- Owner: shared

## Context

CTX-407 verified the Python gRPC server and generated Python stubs. CTX-408 connects the Go API gateway to that Python AI service through generated Go protobuf clients and thin Echo proxy routes. The gateway must remain transport/orchestration code only: it should not duplicate Second Brain or Homelab business logic.

## Scope

- Generate Go protobuf stubs under `src/backend/internal/infrastructure/grpc/pb/`.
- Add Go dependencies for gRPC and protobuf.
- Add `AI_SERVICE_ADDRESS` config with default `localhost:50051`.
- Add an internal AI service gRPC client wrapper.
- Register Echo proxy routes for Second Brain and Homelab service calls.
- Hard-code the current single-user owner ID at the gateway boundary when callers omit `owner_id`.
- Add Go tests with a fake gRPC server proving HTTP routes call the generated gRPC client.

## Out of Scope

- Finance HTTP route implementation.
- Full orchestrator chat loop.
- Auth/audit capability guards.
- Changing the protobuf contract beyond generation/import needs.

## Acceptance Criteria

- [x] Go generated protobuf stubs compile under the backend module.
- [x] Backend config exposes `AI_SERVICE_ADDRESS`, defaulting to `localhost:50051`.
- [x] Gateway registers HTTP routes for capture create/list, Second Brain search/status, Homelab sync/search/link validation, and AI health.
- [x] Routes inject the single-user owner ID when request bodies omit `owner_id`.
- [x] Route tests use a fake gRPC server and prove JSON HTTP requests reach gRPC clients.
- [x] `go test ./...` passes.

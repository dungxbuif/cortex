# Ticket: CTX-411 Python Gateway Orchestrator Full Flow

## Status

- ID: CTX-411
- Status: verified
- Type: feature
- Priority: High
- Phase: PHASE-4-restructuring
- Owner: shared

## Context

Epic 4 already had the package split, provider/repository boundaries, and gRPC contracts, but the OpenAI-compatible chat entrypoint was not connected to the old module services. User direction changed the gateway ownership: Python should own the gateway/orchestrator path, not Go.

## Scope

- Add a deterministic `OrchestratorService` in Python that routes chat messages to existing Second Brain and Homelab services.
- Add Python FastAPI gateway route `/v1/chat/completions` returning OpenAI-compatible response shape.
- Keep one shared PostgreSQL database; isolate modules by tables/repositories only.
- Register `OrchestratorService.ChatCompletions` on Python gRPC as an internal contract.
- Prove full flow through Python gateway and Python gRPC runtime tests.

## Out of Scope

- Full LLM/ReAct loop.
- Permission/audit persistence and capability guards.
- Finance tool adapter wiring.
- Removing existing Go gateway code.

## Acceptance Criteria

- [x] Python gateway exposes `/v1/chat/completions`.
- [x] Chat capture intent writes to Second Brain capture inbox only, not the Vault.
- [x] Homelab chat/search intent reads indexed Homelab chunks and returns source paths.
- [x] Orchestrator uses existing domain services and injected repositories/embedders.
- [x] One PostgreSQL DB remains the runtime store; module isolation is by `secondbrain_*` and `homelab_*` tables.
- [x] Python suite, Go regression suite, and opt-in Google smoke pass.
